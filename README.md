# Diligence Memo Generator

A command-line tool that reads a long investment document (a 10-K or a CIM) and produces a first-pass diligence memo in the format an investment committee expects. Every fact and every number in the memo carries a page citation. Code checks each citation against the source document before it reaches the memo.

```
python diligence.py docs/AVAV_10-K_FY2026_clean.pdf
```

**Sample output** (generated entirely by the tool; not edited by hand):

| | Source document | Memo | LBO model |
|---|---|---|---|
| **AeroVironment** (public, take-private) | FY2026 10-K (SEC EDGAR) | [PDF](samples/AeroVironment_FY2026_10-K_sample_memo.pdf) · [Markdown](samples/AeroVironment_FY2026_10-K_sample_memo.md) | [Excel](samples/AeroVironment_FY2026_10-K_sample_LBO.xlsx) |
| **Northfold Signal Systems** (private, **fictional**) | [Test CIM](samples/Northfold_CIM_FICTIONAL.pdf) with a management case | [PDF](samples/Northfold_FICTIONAL_sample_memo.pdf) · [Markdown](samples/Northfold_FICTIONAL_sample_memo.md) | [Excel](samples/Northfold_FICTIONAL_sample_LBO.xlsx) |

Northfold is an invented company, generated by `tools/make_sample_cim.py` to test the private-company path without putting a real CIM through an API. It contains two deliberately planted narrative-vs-numbers inconsistencies; the memo's Section 8 flags both.

Output: a styled Word memo, a matching PDF, and a Markdown copy. On AeroVironment's FY2026 10-K (138 pages), a full run takes about 20 minutes and costs about $7.25 in API usage. Re-rendering after a code change is free and takes about 30 seconds.

---

## Why this exists

First-pass diligence on a 10-K or CIM is mostly mechanical: find the numbers, find management's explanations, organize them into a standard memo, and flag what doesn't add up. A language model can do that quickly. The problem is trust. A model will produce a confident memo that includes numbers it misread or invented, and in an IC memo one wrong number discredits the whole document.

So the design rule here is simple: **the model is never trusted to cite. Code checks every citation.** Anything that can't be traced to a specific page is removed before it reaches the memo, and every removal is logged.

## What the memo contains

The memo follows [memo_template.md](memo_template.md), section by section:

1. **Executive Summary**: business, scale, key positives and concerns, biggest open question
2. **Business Overview**: segments, revenue model, geography, headcount, M&A history, ownership
3. **Market & Competitive Position**: named competitors, stated advantages, regulatory and budget exposure
4. **Customers, Contracts & Backlog**: concentration, government mix, contract types, funded and unfunded backlog
5. **Financial Summary**: four tables (below), table notes, and commentary
6. **Quality of Earnings Flags**: EBITDA definition and add-backs, impairments, revenue recognition, material weaknesses
7. **Key Risks**: company-specific and ranked
8. **Consistency Check**: places where management's narrative and the numbers disagree
9. **Questions for Management**: one question for every item marked "Not disclosed", plus diligence questions
10. **Appendix: Coverage Notes**: pages read, findings rejected, memo lines deleted

LBO inputs (debt, cash, working capital, taxes, share data, management projections) are not in the memo. They go, with page cites, into the v2 Excel model's Historicals and Cases tabs.

**Section 5 tables.** The model only chooses which reported figure goes in each cell. Code converts units and computes every ratio. Calculated figures are labeled `calc.` and cite their input pages.

| Table | Contents |
|---|---|
| Financial summary | Revenue, growth, gross profit and margin, operating income, EBITDA as reported, Adjusted EBITDA as reported, D&A, capex, backlog, largest customer % |
| Cash conversion & earnings quality | Organic growth, operating cash flow, free cash flow, FCF / Adj. EBITDA, GAAP EBITDA, add-backs (total and excluding impairment), DSO, DIO |
| Balance sheet & liquidity | Total debt, cash + short-term investments, net debt, gross and net leverage, liquidity including undrawn revolver |
| Operating metrics | Funded and total backlog coverage, capex / depreciation, revenue per employee, contract-type mix, segment margins |

Each reported figure in the tables is marked **✓** if the same number for the same year was found independently on a second page of the document, or **†** if it was found on one page only and should be checked by hand.

## How it works

```
 PDF
  │
  ▼
 1. Read pages ─────────── keep each page's printed page number (detected by position, validated)
  │
  ▼
 2. Chunk ──────────────── ~10 pages per chunk, 1-page overlap, each page tagged <page ref="65">
  │
  ▼
 3. Extract (AI) ───────── per chunk: structured findings = claim, number, unit, period, page, exact quote;
  │                         plus a focused MD&A pass for every figure and explanation management states
  ▼
 4. Verify (code) ──────── reject any finding whose quote isn't on the cited page,
  │                         or whose numbers aren't in the quote
  ▼
 5. Tables (AI + code) ─── AI points to the right number for each cell;
  │                         code checks it, converts units, computes the PE metrics, cross-checks pages
  ▼
 6. Write memo (AI) ────── from verified findings + calculated metrics only; cites finding IDs
  │
  ▼
 7. Enforce (code) ─────── delete any line citing a fake ID, an uncited number, or a number not in
  │                         its cited findings; convert IDs to (p. 65) citations
  ▼
 8. Consistency ────────── code: same line item + year stated with values that can't both be right;
  │                         AI pass 1, then AI pass 2 told what was found and asked for what was missed;
  │                         AI items kept only if both sides are cited and every number traces back
  ▼
 9. Render ─────────────── Markdown → styled Word → PDF (exported by Word, so they match)
```

**The division of labor.** The model does what it's good at: reading, classifying, choosing the right figure, and writing. Code does what has to be exact: matching quotes, checking numbers, converting units, and calculating. The model never computes a number. It writes "organic growth was 26.4%" only by citing the code's calculation `[C-ORGANIC_GROWTH-FY2026]`, and the reader sees `(calc.; pp. 81, 116, 118)`.

**Results on the AVAV FY2026 10-K:**
- 1,138 findings extracted (including 197 from the MD&A narrative pass); 1,045 verified, 28 rejected, 65 duplicates from the page overlap removed.
- 64 metrics calculated by code.
- 227 memo lines kept; 1 deleted by the citation check.
- 40 of 69 table inputs independently confirmed on a second page.
- Calculated metrics match a hand calculation, e.g. FCF of $(140.9)M = OCF $(78.4)M − capex $62.5M, and organic growth of 26.4% vs. 140.9% reported.
- Consistency check: 14 items (2 from the code check, 12 from the two AI passes; 8 more AI items failed the citation checks and were dropped). It catches all four issues found by manual review:
  - FDII cited for the FY2026 tax rate, while the reconciliation shows no FY2026 FDII benefit (pp. 60, 111)
  - UGV amortization of $4.6M in MD&A vs. $4.3M in the notes (pp. 33, 69)
  - SG&A of $443.0M in MD&A vs. $443,251K on the income statement (pp. 65, 66), caught by code
  - capex stated three different ways across MD&A, the cash flow statement and the segment note (pp. 72, 84, 125)

## Setup (Windows)

Requirements: Python 3.12, an Anthropic API key, and Microsoft Word (for the PDF; without Word you still get the `.docx` and `.md`).

```
# 1. Create a virtual environment (a private package folder for this project) and install packages
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 2. Add your API key: copy .env.example to .env and paste your key after the = sign
copy .env.example .env

# 3. Test the connection (costs under $0.01)
python diligence.py --check
```

`.env` is listed in `.gitignore` and is never committed. API usage is billed per token by Anthropic, separately from any Claude subscription.

**Getting a 10-K as a PDF.** SEC EDGAR publishes filings as HTML. Download the filing's `.htm` file into `docs/`, then convert it with the included script, which uses Microsoft Edge:

```
.\tools\html_to_pdf.ps1 -Html docs\<filing>.htm -Out docs\<name>.pdf
```

The script shrinks the print slightly so each filing page fits on one PDF page, which keeps the printed page numbers aligned. Automated EDGAR downloads must identify themselves with a name and email in the request's User-Agent header; this is SEC policy.

## Usage

```
python diligence.py docs/<file>.pdf --dry-run     # read and chunk only: page map, chunk map, token estimate. Free.
python diligence.py docs/<file>.pdf --chunk 8     # extract + verify one chunk, to test a prompt change. ~$0.10-0.50.
python diligence.py docs/<file>.pdf               # full run
python diligence.py docs/<file>.pdf --fresh       # ignore saved extraction results and redo everything
```

**Caching.** Every AI call is saved with a fingerprint of its exact prompt, model and settings. On the next run, any step whose inputs haven't changed reuses its saved answer for free. Edit `prompts/write_memo.md`, and only the memo-writing step re-runs.

**Output files:**

| File | What it is |
|---|---|
| `output/<Company>_Diligence_Memo_<date>.pdf / .docx / .md` | The deliverables |
| `output/<doc>/findings.json` | Every verified finding: claim, number, unit, period, page, exact quote |
| `output/<doc>/rejected.json` | Findings that failed verification, with the reason |
| `output/<doc>/calcs.json` | Every calculated metric with its formula and input pages |
| `output/<doc>/citation_log.md` | Every memo line the citation check deleted, with the reason |
| `output/<doc>/draft_raw.md` | The model's draft before enforcement, for audit |

**Settings** live in [config.py](config.py): the model (one line to change), effort level, chunk size, and prices used for the cost log. The cost log prints after every run.

**Prompts** are plain Markdown files in [prompts/](prompts/) and are meant to be edited:

| Prompt | Controls |
|---|---|
| `extract_findings.md` | What gets pulled from each chunk, and the categories |
| `financial_table.md` | Which reported figures feed the tables |
| `write_memo.md` | Memo tone, priorities, and citation rules |
| `consistency_check.md` | What counts as a narrative-vs-numbers problem |
| `extract_narrative.md` | The focused MD&A pass: every figure and explanation management states |
| `lbo_inputs.md` | Which figures feed the LBO, including management projections from a CIM |

## v2: Excel LBO

Every v1 run also writes `output/<doc>/lbo_inputs.json`: every input an LBO needs, each with its value, page cite and source quote. A second command turns that into an Excel model. **v2 makes no AI calls and costs nothing to run.**

```
python lbo.py output/<doc>/lbo_inputs.json                          # build the model
python lbo.py output/<doc>/lbo_inputs.json --consensus-template docs/<ticker>_consensus.csv   # blank consensus file
python lbo.py output/<doc>/lbo_inputs.json --consensus docs/<ticker>_consensus.csv            # add a consensus case
```

Python writes the inputs and the **formulas**; Excel does the math, so every number recalculates when an assumption changes. After building, `lbo.py` has Microsoft Excel (running in the background) recalculate the file, create the sensitivity grids, and confirm there are no formula errors.

| Tab | What it does |
|---|---|
| **Guide** | How to use the model, the color legend, and the overall check status (green / red) |
| **Historicals** | Every sourced figure in blue with its page cite; hover a cell for the exact quote. Public companies also get market value, EV and the current multiple. |
| **Assumptions** | Scenario dropdown; entry (premium to share price, or EV / EBITDA); financing; exit; sponsor equity structure; operating drivers by year and scenario. Placeholders are yellow, each with a note on its basis. |
| **Cases** | *Only when a management case or consensus exists.* The source figures, revenue and EBITDA **haircuts** (flat, or ramping up to the full haircut by the last year), and the resulting sponsor case, which becomes a 4th option in the scenario dropdown |
| **Bridge** | Company adjusted EBITDA to diligence EBITDA: Keep / Deduct each add-back |
| **Sources & Uses** | Purchase price, refinancing, fees, new debt, sponsor equity |
| **Model** | 5-year P&L, NOL usage, cash taxes, free cash flow, revolver, mandatory amortization and cash sweep, credit statistics |
| **Returns** | Exit value, an equity waterfall for a **strip of PIK preferred and common** (default 98% / 2%, or all common; management options dilute the common only), sponsor MOIC and IRR, a value-creation bridge, and two live IRR sensitivity grids |
| **Checks** | 11 integrity checks, 12 with a Cases tab (sources = uses, cash never below minimum, debt never negative, preferred never overpaid, waterfall and bridge tie out, and others), each OK or CHECK |

**Management case (private company).** When a CIM contains multi-year projections, v1 extracts management's revenue, EBITDA and capex by year, each figure with a page cite. On the fictional Northfold CIM, all 15 projected figures were extracted exactly. Entry defaults to an EV / EBITDA multiple, since there is no share price.

**Consensus case (public company).** Consensus estimates aren't in a 10-K, and there's no free source that is both reliable and citable, so the tool reads a simple CSV: year, metric, value, source, as-of date and number of analysts. Fill it from Capital IQ, FactSet or WRDS (I/B/E/S). The reader rejects rows with no source or date, and a file marked TEST ONLY shows a red warning in the model. Automating the pull (the Capital IQ Excel plug-in, or WRDS's Python package) would write the same file.

**How the model was verified.** An independent Python re-implementation of the same deal math was compared with Excel's results. They match exactly on:
- 273 cells across 7 cases (all three scenarios, diligence EBITDA, multiple-based entry, sweep off, and a stress case that draws the revolver);
- the returns and waterfall for both equity structures;
- individual cells in the sensitivity grids; and
- the consensus and management cases with flat and ramped haircuts.

The Checks tab was also tested by breaking the model on purpose; each break was flagged correctly.

**LBO simplifications** (also listed on the Guide tab):
- Interest is charged on beginning-of-year debt balances, which avoids a circular reference.
- Depreciation excludes amortization of acquired intangibles, so the tax shield is understated.
- NOLs offset taxable income without annual (Section 382) limits.
- There is one equity investment and one exit, with no dividends.
- Management options are modeled as a pool percentage of the common's gain.
- In the Management / Consensus case, depreciation, working capital and tax follow the Base case.

```
lbo.py                  v2: builds the Excel LBO from lbo_inputs.json (no AI)

src/
  pdf_pages.py          PDF -> pages with printed page numbers
  chunker.py            pages -> overlapping, page-tagged chunks
  extract.py            chunk -> structured findings (AI, JSON schema enforced)
  verify.py             findings -> verified / rejected (code only)
  pipeline.py           runs extract + verify over the document, with caching
  fintable.py           table inputs (AI) + unit conversion, PE metrics, cross-checks (code)
  synthesize.py         verified findings + metrics -> memo draft (AI)
  citations.py          citation enforcement on every memo line (code only)
  consistency.py        narrative-vs-numbers check (AI) + two-sided citation check (code)
  crosscheck.py         code-only check: same line item and year stated with conflicting values
  render.py             Markdown -> styled Word -> PDF
  llm.py                the only file that calls the API; cost logging and caching
  lbo_inputs.py         LBO inputs incl. management projections, with cites -> lbo_inputs.json
  consensus.py          reads and validates a consensus estimates CSV
  lbo_model.py          writes the Excel LBO (inputs and formulas)
  excel_com.py          drives Microsoft Excel to recalculate, add sensitivity grids, check and test
tools/html_to_pdf.ps1   EDGAR HTML -> page-aligned PDF
tools/make_sample_cim.py  generates the fictional Northfold CIM used for testing
samples/                memos and LBO models generated by the tool (AVAV 10-K; fictional Northfold CIM)
```

## Known limitations

Ranked by how much they matter for trusting the output.

1. **The citation check confirms numbers, not meaning.** A memo line survives if its numbers appear in the findings it cites. A line could still cite a real finding and misstate it in words (e.g. "rose" when the figure fell, or the wrong segment). Sentences with no numbers only need a valid citation. *Fix planned:* a second, cheaper model checks that each line says what its cited finding says.
2. **The AI part of the consistency check still varies between runs.** The code layer is deterministic, but it only compares line items it can name with confidence (revenue, SG&A, capex, operating cash flow and similar). Everything else depends on the two AI passes. Before the second pass and the MD&A narrative pass were added, one run caught the FDII issue and the next didn't. The current version catches all four known issues, but repeatability across fresh runs hasn't been measured; that would cost about $1.30 per trial.
3. **Year and unit checks are strongest in the tables.** Table inputs are cross-checked against a second page (✓/†). Numbers in the memo text are checked against a finding, but a finding with the wrong year attached would pass. Extraction captures unit labels ("$ thousands") from the page, but nothing confirms them independently.
4. **The model can miss table inputs.** On AVAV it did not pick up the FY2025 goodwill impairment ($18.4M), so one FY2025 metric shows n/a. A gap shows as "Not disclosed" or "n/a", never as an invented number, but some gaps are misses rather than true non-disclosure.
5. **Some correct findings are rejected.** Product names containing numbers (e.g. "Puma 3", "VAPOR 55") can trip the number check. About 4 of the 24 AVAV rejections are this kind of false positive.
6. **Document scope.** Tested on one EDGAR 10-K and one short fictional CIM; not yet on a real CIM. Scanned or image-only PDFs aren't supported. Printed page numbers are detected from page footers; documents without them are cited by PDF page ("PDF 12"). PDF text extraction flattens tables into rows of numbers, so column alignment has to be inferred.
7. **Data handling.** Document text is sent to Anthropic's API. Don't run confidential documents (e.g. a CIM under NDA) without authorization from whoever controls them.

**Out of scope:** web interface, database, multi-document comparison. Valuation and returns live in the v2 Excel LBO, not in the memo.

| Step | API calls | Cost |
|---|---|---|
| Extraction (16 chunks) | 16 | $3.96 |
| MD&A narrative pass (2 chunks) | 2 | $0.81 |
| Table inputs | 1 | $0.34 |
| Memo draft | 1 | $0.86 |
